# Reanimation Table v0.5.3 handover

The v0.5.3 release on `feature/hearts-native-health` uses the existing pack UUIDs and sets both headers, their modules and the resource dependency to `[0, 5, 3]`. The user confirmed v0.5.1 recovery in retail and reported garbled ingredient labels in the v0.5.2 form. [Import v0.5.3](dist/hearts-and-lives-v0.5.3.mcaddon) · [v0.5.2 interface](dist/hearts-and-lives-v0.5.2.mcaddon) · [v0.5.1 gameplay baseline](dist/hearts-and-lives-v0.5.1.mcaddon)

## Recovery

The native dropdown shows the player's permanent hearts and the selected Full Heart or Half Heart recipe. Each of the three rows keeps its Mojang item texture and a short caption such as **Diamond 4/6 - Need 2**. Counts show how much of the selected recipe is covered. Surplus inventory cannot widen a row. Green **Ready** and red **Need** text carry the same meaning without colour. The only purchase control is **RESTORE HEART**. The last half heart is preselected when it is the only size that fits.

The installed Windows 1.26.65.1 Mojangles and Minecraft Ten fonts lack the v0.5.2 check mark (U+2713). Both the check mark and the multiplication-sign cross were replaced with words. Printed ingredient captions use ASCII, and formatting codes sit outside the complete caption so there are no spaces next to a code. Half-heart totals use a decimal point. Putting the total in the dropdown caption and removing the quantity legend saves two rows. The short names **Netherite** and **Sea Heart** keep the full item textures beside their counts.

The v0.5.1 and v0.5.2 interaction adapters both returned before opening the table when an ordinary item was held. In v0.5.2 the form opened in retail Windows after switching from a stack of tables to an empty slot. Standing use now opens the table even with a block, tool or ingredient selected. Sneak-use with a building block still allows placement. Opening remains deferred out of the cancellable before-event. A failed form opening gives the player a retry message and writes the exception and table location to the host Content Log.

A confirmed grant replaces the recipe with the updated count and a short message. Players can dismiss this immediately or let it close after about two to three seconds of gameplay. Opening at ten hearts shows only the count, **ALL HEARTS RESTORED!** and Close. Previously crafted Artificial Hearts still use the held-item redemption path.

Only Normal material prices have approval. Easy, Hard and Extreme currently point to those prices. Host-only preset and cooldown commands retain their existing behavior. [Recipe data](src/recovery-materials.ts) · [Player guide and prices](README.md#using-the-station)

## Choice of interface

- **Stable server forms.** Mojang released `CustomForm` and observable controls in stable `@minecraft/server-ui` 2.1.0. Bedrock 26.60 released dropdown tooltips and button icons in stable 2.3.0, the dependency pinned in these packs. The dropdown is one controller focus stop. Three disabled image buttons display the ingredients. Minecraft controls their width, height and scrolling at the user's GUI scale. [26.30 retail release](https://www.minecraft.net/en-us/article/minecraft-26-30-bedrock-changelog) · [26.60 retail release](https://www.minecraft.net/en-us/article/minecraft--bedrock-edition-26-60-changelog) · [CustomForm API](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server-ui/customform?view=minecraft-bedrock-stable) · [Mojang item textures](https://github.com/Mojang/bedrock-samples/tree/15701fa9c13923f12662984c32c124327e40e3d3/resource_pack/textures/items)
- **Resource-pack JSON UI.** The published server-form example adds controls to Minecraft's shared `server_form` screen and binds to the form data the client already exposes. Using it for this table would couple the pack to that shared screen and its bindings. The supported script form provides a per-player entry point and the required controls. [Mojang server-form definition](https://github.com/Mojang/bedrock-samples/blob/15701fa9c13923f12662984c32c124327e40e3d3/resource_pack/ui/server_form.json) · [Server-form modification example](https://wiki.bedrock.dev/json-ui/modifying-server-forms)
- **Crafting and containers.** A custom crafting table selects recipes by tag and produces their item results. A block container exposes transferable inventory slots. Neither documented interface provides a slot action that verifies and commits a player's life grant and material payment together. Keeping the script transaction also lets two players share a table with independent inventories. [Crafting-table component](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockreference/examples/blockcomponents/minecraftblock_crafting_table?view=minecraft-bedrock-stable) · [Shaped recipe result](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/recipereference/examples/recipedefinitions/minecraftrecipe_shaped?view=minecraft-bedrock-stable) · [Block container properties](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockreference/examples/blockcomponents/minecraftblock_block_entity?view=minecraft-bedrock-stable)

## Save behavior

Only the size selector is client-writable. Each recipe’s Restore callback is bound to its own price and must still be the visible, enabled choice. The form accepts one purchase per opening. Confirmation calls the existing host transaction after rechecking the session, placed block, six-block proximity, dimension and settings. The transaction rechecks life state, cooldown and inventory. Returning its committed state lets the same form display the new total.

The transaction verifies each affected slot and the saved grant. Confirmed failures refund the exact debits, including partial stacks. If a storage read cannot establish whether a grant committed, the host receives an error. Bedrock saves inventory and world properties separately, so a hard process shutdown between writes can leave a mismatch. Native health retries use the committed balance and never charge again.

## Validation

All 100 Hearts & Lives tests passed against the compiled project and again against scripts extracted from the v0.5.3 add-on. The six new tests cover the actual block-event-to-form path, held items, hotbar changes, failed opens and retry, printable ingredient captions across both recipes, and the reduced control count. The separate native probe suite passed five tests and validated both probe archives.

A separate retail Bedrock Dedicated Server 1.26.65.1 fixture loaded the exported pack with experiments off. Its native UI module exposed every form method used by the table, and a runtime check exercised the Boolean, String and writable Number observables, including subscription and unsubscription. No player joined the fixture.

Both nested archives passed validation, including all 20 native health groups. A payload comparison with v0.5.2 found changes in the two manifests, `scripts/lives-bedrock.js`, `scripts/recovery-form.js` and three display names in `scripts/recovery-materials.js`. The recipe IDs, amounts and debit code match byte-for-byte after accounting for those display names. The progression, transaction and native health scripts, block, crafting recipe, legacy items and textures match v0.5.1 and v0.5.2.

An offline check extracted all 18 distinct ingredient captions from the packaged form. The longest was 22 printable characters. At an 8-pixel font size, the widest measured 103 pixels in Mojangles and 95 in Minecraft Ten. Visual fit, scrolling and controller focus still need a v0.5.3 Windows client and a PS5 guest at normal play resolution and GUI scale.
